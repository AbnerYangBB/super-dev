# AGENTS 协作规范

## 0) 沟通原则

- 动手前先确认真实目标、用户场景、成功标准、主要风险与边界归属.
- 如果用户给出的实现方式不是解决其表述问题的最优解，先终止实现, 并提出更合适的方案与理由. 
- 对话时使用中文，技术术语可保留英文.
- 当功能的实现计划中, 涉及到兼容旧逻辑时, 终止任务, 优先向人类提问是否需要兼容, 而不是默认执行.

## 1) 能力使用

- 优先使用已经配置的MCP服务, 其次是 skill.

## 2) 代码检索

- 读取遵循最小必要原则，避免无差别全量扫描. 
- 优先读取`docs/overview/locaf-app-ios-page-flow.md`来快速了解项目overview.
- 优先使用子agent进行代码检索等简单任务, 需要完成`思考/审查/提出方案/脑暴`等主观性较强的任务时由你自己完成.

## 3) 代码生成原则

- 不要把所有实现堆积在一个文件中, 保持良好的架构设计和组件化.
- 代码中不允许出现中文字符串, 每个独立的功能块, 函数, 以及UI层级, 需要增加中文注释.

## 4) 代码校验(按需使用)

- 读取根目录下的`ResultVerification.md`来了解.

## 5) 交付输出规范

- 明确说明：改了什么、为什么改、影响哪些文件
- 明确说明：执行了哪些验证（编译/运行/测试）以及结果.
- 明确说明：未执行项及原因（工具缺失、设备不可用、权限限制等）.
